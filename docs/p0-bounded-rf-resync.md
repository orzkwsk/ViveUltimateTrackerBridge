# P0 bounded RF resynchronization (offline)

The inherited `dev` implementation (`cf8c576f5ef3af75f781e2bb8691c10c3cd77207`, retained in PR #7 base `a47d1920cd65ba53077f6f27b2196a25998678a7`) rejected every pose more than 500ms after the last admitted pose. Rejection never advanced that accepted timestamp, so 600ms silence permanently stopped publication despite transport state `Running`. The independent reproducer and the fresh before-build show 1 accepted/1 sent, 20 gap rejections, same session and no HID writes.

Each configured MAC now owns a separate quarantined candidate `{receive time, RF index, packet count}`. After a gap greater than 500ms the first structurally valid packet is an independent anchor, without comparing its RF index to the obsolete pre-gap phase. Two further strictly later packets must each have an RF delta in 1..127 and an inter-candidate interval at most 500ms. Only the third/current packet is mapped and admitted; predecessor poses are never queued. The admitted timestamp, RF baseline, sequence, UI accepted age and mapping do not change during quarantine. Three packets are a finite serial coherence rule, not physical tracking-quality certification.

Duplicate, reverse and half-range 128 candidate deltas reject and clear the candidate; candidate time regression does likewise. Another candidate gap greater than 500ms reseeds quarantine without publication. Generation, epoch, configured device, absence, exact event/pose MAC+slot and immutable timestamp checks precede candidate mutation. Default ServiceRuntime additionally refuses a current-session pose without authoritative registry ownership (or after a registry fault) before adapter mutation/publication, preserving event-time cleanup. Existing generation/epoch rejection counters remain reachable. Explicit pair-after-absence restart policy is unchanged.

`Running` denotes a live transport. Local `resyncPending`, `resyncStarted`, `resyncCompleted`, `resyncReset` counters expose the independent recovery state; Agent's existing output text includes pending/completed totals. While candidates are pending the existing device UI remains `STALE`/`Unknown`, with no accepted-receipt refresh. Peers retain their own admission streams, output sequences, source session, coordinate revision and configured map. The wire-v2 codec, generated kit, schemas, published native ABI, setup/pairing and Agent/UI lifecycle are unchanged.

Mapping remains vendor-evidence based: Ok is FULL only with valid position and quaternion; RecentlyLost 0x04/0x14 is ROTATION_ONLY with valid quaternion; Lost 0x03/0x13 is NONE. Invalid numbers cannot promote validity. Recovery itself never promotes a sample to FULL.

## Reproducible checks

- `vut_resync_tests`: actual adapter and decoder/codec; all 256 first post-gap RF phases, wrap, three-packet quarantine, unchanged 500ms continuous bound, bad candidate chains, stale provenance/time/identity, absence and vendor validity.
- `vut_runtime_resync_tests`: memory-HID bytes through actual Backend/vendor decoder, **default** ServiceRuntime stage, Publisher and codec; 600ms loss with live peer, 20 fresh frames, stale UI/admitted ages during quarantine, latest-only recovery, same session/revision/map, raw optical loss and invalid numbers, ownership rejection followed by valid receive/aging. No injected `admit=true` stage.
- `vut_p0_runtime_replay OUTPUT SESSION_UUID REVISION`: test-only exporter.100recorded pose37 frames, changing only raw RF/status; actual 600ms pause before index 40; statuses 0..39/60..99 FULL, 40..49 RecentlyLost, 50..59 Lost. 98 actual Publisher frames are saved as JSONL `{received_at_ns,envelope}`. The envelope is the exact Send byte string, never re-encoded; receive time is recovered from the immutable timestamp plus its fixed session epoch. Existing output files are refused.
- `p0_runtime_publisher_replay`: validates capture sequence, one measured silence, immutable epoch, FULL 80/ROTATION_ONLY 8/NONE 10 and overwrite preservation. The older adapter-only exporter remains independently available.

The exporter and memory HID are test-only and must not be packaged as product runtime. Build normal `vut_service.exe` via CMake. WPF is built separately from unchanged `ui/Control.Wpf`; CMake has no managed-copy rule. A framework-dependent GUI package needs adjacent `Control.Wpf.exe`, `Control.Wpf.dll`, `Control.Core.dll`, `Control.Wpf.deps.json`, `Control.Wpf.runtimeconfig.json` plus the installed Windows Desktop .NET 8 runtime (and the native MSVC runtime). Agent uses explicit `--tray --gui=ABSOLUTE_WPF_EXE`; no default or launcher is changed.

Windows Release and offline test results/hashes are recorded in the task's external `S-B/impl` evidence. Physical HID/dongle, Hub, SteamVR, HMD, real multi-tracker behavior, PHYSICAL_HIL and CUTOVER are NOT_RUN. Software capture is not hardware acceptance.
